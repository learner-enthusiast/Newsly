# Task: "Video script" pipeline for individual news pages (Dainik Samachar)

From a news item, generate a researched, fact-checked talking-head video script, creative/editing
direction, image results, optional AI prompts, a publishing kit, and a hand-off pack that a local AI
CLI turns into a finished video with Remotion. Triggered by a button on the news page; results on
`/news/[id]/script`.

## Read first
Read `prisma/schema.prisma` (news model + its source/article relations), the individual news page
(`/news/[id]`), `inngest/` (client, index, functions), `lib/clients/` (OpenAI, SerpApi, Firecrawl,
any web search client), Clerk setup and existing agent conventions BEFORE coding. Reuse them; do not
duplicate models or clients. Ask me if the news page route is not `/news/[id]`.

## Docs (fetch before use; STOP and ask if unclear — never guess endpoints, params or fields)
- Inngest v4: https://www.inngest.com/docs/reference/typescript/v4/intro
- OpenAI structured outputs: https://platform.openai.com/docs/guides/structured-outputs
- OpenAI image generation (to write prompt SUGGESTIONS only): https://platform.openai.com/docs/guides/image-generation
- SerpApi Google Images: https://serpapi.com/google-images-api
- SerpApi Google Images Light: https://serpapi.com/google-images-light-api
- SerpApi Bing Images: https://serpapi.com/bing-images-api
- SerpApi Google News: https://serpapi.com/google-news-api
- Optional: Pexels (photos + videos) https://www.pexels.com/api/documentation/ ,
  Wikimedia Commons API https://commons.wikimedia.org/w/api.php
- Remotion: https://www.remotion.dev/docs/

## Hard rules
1. Every agent: `agents/video/<name>/{schema.ts, prompt.ts, index.ts, <name>.test.ts}`; zod input AND
   output, validate both; export PROMPT_VERSION; never throw — return status "failed" + reason.
2. Facts come ONLY from the FactSheet (built from the news row and its sources). Nothing from model memory.
   No investment advice. Finance stories carry "For information only, not investment advice."
3. The pipeline NEVER generates images or videos. AI prompts are optional suggestions only.
4. Not every beat needs a visual. Empty beats are fine.
5. Every external call goes through the existing call wrapper (cache, retry, budget) if the repo has one;
   otherwise create `lib/clients/callTool.ts` (cache by hash, retries 1s/2s/4s, per-run budget, returns null on failure).
6. Idempotent: re-clicking returns the existing script unless "Regenerate" is used.
7. AI prompt suggestions: no real identifiable people, no real logos/trademarks, no fake documents or headlines.

## PHASE 1 — Data model + trigger + page shell
### Prisma
```prisma
model VideoScript {

  error          String?

  minSec         Int      @default(60)
  maxSec         Int      @default(140)   // soft limit (±10%)
  pace           String   @default("normal") // slow | normal | fast
  aspectRatio    String   @default("9:16")   // "9:16" | "16:9"
  estimatedSec   Int?
  lengthReason   String?

  script         Json?    // ScriptOutput
  factCheck      Json?
  direction      Json?    // CreativeDirection
  publishing     Json?    // PublishingKit
  editPack       Json?
  recordingBrief String?  // markdown

  promptVersions Json?    // { agentName: version }
  assets         VisualAsset[]
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt
  @@index([newsId])
}

## PHASE 2 — Research + script + fact check
### researchBuilder
Input: whole news row + its stored sources (existing models).
1. Collect stored source texts; fetch missing full text via the Firecrawl client (max 5 pages, cached).
2. If fewer than 2 usable sources OR the news is older than 48h: 1–3 extra searches (SerpApi Google News;
   other existing web-search client if available) for latest update/background; fetch ≤ 3 new pages;
   store as sources with URLs.
3. Output FactSheet:
```ts
{ facts: [{ id, text, type: "number"|"date"|"name"|"event"|"quote"|"context", value?, sourceIds: string[],
            sourceUrls: string[], confidence: "high"|"medium" }],
  whatHappened, whatChanged, whyItMatters: string[], whoIsAffected: string[], openQuestions: string[],
  conflicts: [{ factA, factB, note }] }
```
Quotes verbatim with speaker; numbers exactly as in the source (unit, currency); conflicts recorded, never picked silently.
### scriptWriter
- Input: FactSheet + news row + `{ language, minSec, maxSec, pace, aspectRatio }`.
- Length from content, never padded: thin (≤ 6 strong facts) ~60–75s; normal ~90–120s; rich up to ~140s.
  Output `estimatedSec` + `lengthReason`.
- Words/sec (configurable constants): English slow 2.0 / normal 2.4 / fast 2.8; Hindi 1.9 / 2.2 / 2.6.
  Beat start/end from cumulative words ÷ wps.
- Structure: hook (≤ 5s: surprising number, question or consequence) → what happened → key numbers →
  why it matters / who's affected → what to watch next → CTA (≤ 5s). 8–18 beats.
- Output: `{ title, hookOptions: string[3], beats: [{ index, startSec, endSec, spokenText, onScreenText? (≤ 6 words),
  kind: "fact"|"explain", factIds: string[], priority: "core"|"optional", cutNote? }], cta, wordCount, estimatedSec, lengthReason }`.
  Mark extra beats "optional" so the creator can cut. Conversational, one person talking to camera.
### factChecker
- Every number, date, name, quote in each beat must match a FactSheet fact (normalise formats like
  ₹1,200 cr = 1200 crore). Output `{ beats: [{ index, status: "ok"|"fixed"|"removed_claim", issues }], passed }`.
- Failing sentences: rewrite once using only FactSheet facts, re-check; unfixable claims removed. Never add facts.
- Unit test: every number in the final script exists in the FactSheet.
### UI
Tabs "Script" (beats, times, optional badges, fact chips linking to facts, fact-check badge, hook options,
estimatedSec + lengthReason in the header, Copy script) and "Fact sheet" (facts with source links,
conflicts highlighted, open questions).
CHECKPOINT: one thin story → ~1:00–1:15; one rich story → ~2:00–2:20; fact check passes. Commit.

## PHASE 3 — Creative direction (senior content creator + professional editor)
### creativeDirector
Input: script + FactSheet + aspectRatio. Output per beat:
`{ index, needsVisual, overlayType: "none"|"image"|"logo"|"chart"|"text_card"|"video_broll"|"map",
   searchQueries: string[] (≤ 3; only for image/logo/video_broll),
   editing: { transitionIn, transitionOut, motion, textAnimation?, speakerFraming: "normal"|"punch-in 115%",
              sfx?, musicCue? }, editorNote }`
plus global `{ pacing, hookTreatment, subtitleStyle, colorTreatment, musicMood }`.
Apply pro rules, e.g.: company first named → name callout + logo reveal from behind the speaker (scale + slide);
numbers → animated count-up chart/text card, not a photo; change visual every 3–6s in dense parts; punch-in on
key lines; leave beats without overlays when the speaker alone is stronger; hook gets the strongest visual.
### UI
Per beat: editor note + editing chips; global direction card.
CHECKPOINT: every beat has editing direction; some beats have no visual. Commit.

## PHASE 4 — Images + optional AI prompts
### imageFinder (any source, no licence filter)
- image/logo beats: SerpApi Google Images → Google Images Light → Bing Images (next only if < 3 usable results);
  Pexels/Wikimedia only if keys exist. video_broll: Pexels Videos if `PEXELS_API_KEY`, else skip.
- ≤ 6 candidates per beat (cache 7 days, budget); LLM ranks by relevance (text only); keep top 4.
  Logos: prefer official logo / press-kit results. Store URLs only, never download.
### genPrompter (optional)
Only for beats with needsVisual AND (no good result OR director prefers generative).
Per beat: 1–3 image prompts + 0–2 video prompts
`{ kind, prompt, negativePrompt?, style, aspectRatio, durationSec?, cameraMove?, notes }`, tool-neutral
(OpenAI or any image/video model).
### UI
Per beat: image cards (preview, source, open page) + collapsible "AI suggestions (optional)" with Copy buttons.
CHECKPOINT: image beats show results; prompts only where needed. Commit.

## PHASE 5 — Publishing kit
### publishingKit
Input: final script + FactSheet + direction + language. Output:
```ts
{ titles: [{ text, style: "curiosity"|"direct"|"number"|"question"|"hindi_english_mix", charCount }], // 5, ≤ 70 chars preferred
  thumbnail: { concepts: [{ idea, textOverlay /* ≤ 4 words */, layout }], // 3
               openaiPrompts: [{ prompt, size, notes }], // 2–3; background/scene only, leaving space for the creator's face from a video frame
               tips: string[] },
  descriptions: { youtube /* summary, key points, "Sources:" URLs from FactSheet, "Chapters:" placeholder, disclaimer */,
                  shorts /* ≤ 2 lines */, instagram, x /* ≤ 280 chars */ },
  hashtags: string[] /* 5–10 */, pinnedComment: string }
```
Titles/thumbnails must not claim anything the script doesn't say.
### UI
Tab "Publishing kit": titles with char counts, hook options, thumbnail concepts + Copy prompt,
descriptions per platform with Copy, hashtags, pinned comment.
CHECKPOINT: kit complete for one story. Commit.

## PHASE 6 — Hand-off pack, render prompt, static setup guide
### editPackBuilder
- `editPack` (zod-validated):
```ts
{ version: 1, newsId, title, language, aspectRatio, fps: 30, maxSec,
  speaker: { clip: "speaker.mp4", placement: "bottom", headSafeZone: "top 45%" },
  global: { pacing, subtitleStyle, colorTreatment, musicMood, hookTreatment },
  beats: [{ index, scriptText, priority, factIds,
            overlay: { type, file?: "assets/beat-<index>.<ext>", candidates: [{ url, pageUrl }], aiPrompts: [], text? },
           ingBrief` (markdown, LLM-written): framing (head + shoulders in lower half, top ~45% clear), eye-level
  camera, quiet room, full script with beat numbers and [PAUSE] marks, optional beats marked "can cut",
  cutting steps (remove gaps/retakes, cut optional beats if needed, keep beat order, export `speaker.mp4`,
  save chosen visuals as `assets/beat-<n>.<ext>`).
- `renderPrompt` (markdown TEMPLATE, not LLM-written):
  1. "Work only inside this folder. Read edit-pack.json, speaker.mp4 and assets/."
  2. "speaker.mp4 was cut by hand, so script times no longer match. Transcribe it with word timestamps
     (OpenAI transcription if OPENAI_API_KEY is set, otherwise local Whisper e.g. whisper.cpp) and align each
     beat to where its scriptText is actually spoken. Skip beats that were cut."
  3. "Create or reuse ./remotion. Speaker full-frame; overlays above the head in the safe zone; apply each beat's
     editing (transitions, motion, punch-ins, text animations); build charts, text cards and logo reveals as
     Remotion components; burn subtitles from the transcript in global.subtitleStyle. Missing beat file →
     download its first candidate URL → else, if OPENAI_API_KEY is set, generate from its first aiPrompt →
     else render a text card."
  4. "Use music/SFX only if files exist in assets/audio. Show me one frame per beat before the final render.
     Render out/final.mp4 at aspectRatio/fps. Write out/chapters.txt (YouTube chapters from surviving beats,
     first at 0:00) and out/description.md (youtube description with chapters filled in).
     Ask before guessing anything not in edit-pack.json."
### Static setup guide (NOT AI-generated)
- Split `content/video-setup/SOURCE.md` (already in the repo, written by me) into `common.md`, `claude-code.md`,
  `codex.md`, `cursor.md`, `gemini.md`, `other.md` VERBATIM. Do not add install commands I didn't write.
- UI: "Which AI coding tool do you use?" selector (remember in localStorage) → shows common + tool file.
  The Render prompt tab prepends the tool's one-line opener.
### UI tabs
"Recording brief" · "Setup guide" · "Render prompt" (Copy) · "edit-pack.json" (Download) · Regenerate button.
CHECKPOINT: edit pack validates; every tool option shows its guide; Copy/Download work. Commit.
